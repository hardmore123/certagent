# 周报（2026-08-31 ~ 09-03）· ReportVerify 报告草稿准确性核对

## 一、本周工作进展

1. **LLM 集成落地并真实端到端验证**：ReportVerify 恢复并完成可选 LLM 集成，30 个必需任务全部收口。复用 CertAgent 聚好看 higpt-new 网关（deepseek-v4-flash），凭据仅通过项目根 `.env` 受控注入（已 gitignore，不入库、不入日志）；新增 `env_bootstrap.py` 启动时自动加载 `.env`（真实环境变量优先、不覆盖）。真实链路已跑通：网关可达（HTTP 200）、差异解释成功产出，全量测试 357 项通过。

2. **差异解释分批与并发**：真实网关下单批 200 行差异会超墙钟预算并触发超时，改为按批（默认每批 50 行）+ 范围上限 + 线程池并发（默认 4）执行，把 LLM 阶段墙钟耗时从"批数×单批"压到约"批数/并发×单批"；超上限只解释前 N 条，其余差异仍完整保留确定性证据。

3. **候选跨文档护栏修复**：候选匹配的相容判断从"物理表号相等"改为"block_type 相同 + 分组相容"，修复跨文档候选被误判为跨表的问题。

4. **前端重写为三视图 + AI 建议只读区**：前端改为 CertAgent 青色风格，工作台 / 历史记录 / 确认差异三个独立视图，新增 LLM 开关下拉与 AI 建议只读展示区，明确"AI 仅供人工复核，不改变确定性结论与下载门禁"。

5. **AI 解释改为行内内联**：AI 差异解释（含风险、学科建议）从底部单独版面改为按 `diff_key` 映射、内联渲染到每行差异正下方的只读卡片，解决"AI 建议与对应差异割裂、需要来回对照"的体验问题；底部面板仅保留跨行的匹配候选。同时把单次解释上限从 200 提升到 500 条（三处配置一致 + `.env` 显式配置）。

6. **修复大文件上传报错（本周较关键）**：定位"There was an error parsing the body"根因——Starlette 新版把 multipart 单 part 默认上限降到 1MiB，正常 .doc/.docx（个别含内嵌对象达上百 MB）会在进入业务逻辑前就被判 400。改为手动 `request.form(max_part_size=...)` 放开到业务上限（默认 500MB），真实大小仍由逐块累加以 413 兜底。同一 140MB 样本从 400 修复为 202 创建成功。

7. **新增任务计时（实时 + 阶段明细）**：后端在 Job 记录 `started_at/finished_at` 与各阶段墙钟耗时（解析核对 / AI 解释 / 总耗时），summary 派生 `elapsed_seconds`；前端工作台运行期显示实时"已用时 mm:ss"，完成后展示阶段耗时明细，历史记录表新增"耗时"列。真实小文件验证：确定性核对 15.96s / 总 15.97s，字段正确产出。
