# 记忆库说明（供管理者整理与优化）

系统把每次人工在"差异确认页"做的决策（含理由）**追加落盘**，形成长期记忆，用于后续自动反哺建议（历史多次被否→预置忽略/降置信；多次确认→升置信）。本文说明它写在哪、什么格式、怎么整理。

## 一、写在哪里

- **默认文件**：`list-merge-demo/runs/feedback.jsonl`
- **可改位置**：设置环境变量 `FEEDBACK_FILE=你的路径`（或写进 `.env`）即可改到别处（如共享盘），便于集中管理。
- **写入格式**：JSONL —— 每行一条 JSON 记录，只追加不覆盖。
- **写入时机**：每次在确认页点"提交决策"后，本批次所有决策各写一行。

## 二、每条记录的字段

```json
{
  "ts": "2026-08-18T14:30:05",         // 决策时间
  "key": "changed-12",                  // 差异行的内部键
  "verdict": "reject_pair",             // 裁决（见下表）
  "reason": "厂商全称/简称差异，非实质变更",  // 人工填写的理由（选填）
  "sig": "changed|机内电源单元|55431-f",  // 身份指纹：diff类型|归一件名|归一型号
  "context": {
    "关键件名称": "机内电源单元",
    "型号": "55431-F",
    "diff类型": "changed",
    "changed_fields": ["制造商"],
    "pair": {                            // 仅手动/AI配对时有
      "orig_name": "...", "plm_name": "...", "confidence": 0.0, "reason": "手动匹配"
    }
  }
}
```

### verdict 取值含义
| verdict | 含义 |
|---|---|
| `accept` | 接受系统判定 |
| `reject` | 直接丢弃该行 |
| `ignore` | 记忆预置忽略（历史多次被否时系统自动建议） |
| `reject_dup` | 独有项手动匹配 → 合并为"相同" |
| `reject_pair` | 独有项手动匹配 → 配对为"内容不同" |
| `reject_same` | "内容不同"其实相同 |
| `reject_split` | "内容不同"拆成两个独有项 |
| `unpair` | 拒绝 AI 提名配对，拆开保留 |

> **指纹 `sig`** 是整理的关键：同一个"件+差异类型"跨任务用同一 sig，便于聚合"这个件被否/被确认了多少次"。

## 三、系统如何用这些记忆（自动）

- 新任务比对后生成建议时，按 `sig` 聚合历史 `accept`/`reject` 计数：
  - 被否 ≥ `MEMORY_STRONG_MIN`（默认 2）次且否多于认 → 建议**预置忽略**、置信度降为低，并在确认页标注"历史 N 次否决"。
  - 被确认 ≥ 阈值 → 置信度升为高，减少重复确认。
- 开关：`.env` 里 `MEMORY_ENABLED=true/false`、`MEMORY_STRONG_MIN=2`。

## 四、管理者如何整理（人工）

1. **直接看**：用文本/Excel 打开 `runs/feedback.jsonl`（每行一条 JSON），可按 `sig`、`verdict`、`reason` 排序筛选。
2. **挖掘高频被否模式**（候选误报规则）：调用 `compare_core.memory.mine_reject_rules(min_rejects=2)`，返回按被否次数排序的模式列表（含件名/型号/变更字段/理由样例），供人工决定是否沉淀为反向规则。
3. **挖掘同一件别名对**：`compare_core.memory.mine_aliases()`，返回被反复确认为"同一件"的名称别名对，可用于后续减少配对误报。
4. **沉淀成规则**：把确认稳定的模式手工写进
   - 反向规则（误报防护）：`compare_core/rules/data/avoidance/false_positive.yaml`
   - 正向规则（匹配/比对字段）：`compare_core/rules/data/merge_rules.yaml`

## 五、注意

- 该文件是**追加写**，会持续增长；定期归档旧记录即可。
- 记录里含关键件名称/型号等业务信息，按公司数据规范存放（如放共享盘请注意权限）。
- 想清空记忆重新积累：备份后删除 `runs/feedback.jsonl` 即可（系统会自动重建）。
