## 1. 这个项目做什么

两份 Word 关键件**清单**（A=原始/旧版本、B=PLM 新品/新版本）→ 判断差异 → AI 建议 → 人工确认（接受 / 拒绝 / 手动匹配纠正 / 其实相同 / 拆两独有）→ 生成【整合版关键件清单】+【变更前后对照表】，并把决策沉淀进长期记忆用于持续优化。

关键动词是**合并 / 整合**（不是"核对"——核对是项目二做的事）。

状态：**已完成、已部署上线、已上传 GitLab**。

## 3. 架构（分层，依赖单向）

```
CLI(cli.py) / Web(webapi) → 编排层 graph/(LangGraph,可选) → 核心引擎 compare_core/(独立可单跑)
                                                            解析 → 判断(diff) → 建议(规则+LLM) → 写Word → 记忆
```

- 核心引擎 `compare_core/` 不依赖 LangGraph，可 CLI 直接跑（默认）。
- `graph/` 用 LangGraph + `interrupt` 实现人在环。
- `webapi/` FastAPI Web 服务，前端确认页人工决策。

## 4. 核心引擎 compare_core 子模块

| 子模块 | 文件 | 职责 |
|---|---|---|
| `parser/` | `converter.py` / `docx_parser.py` | .doc→.docx 转换（Word COM / LibreOffice）+ 表格解析（容错重心：合并单元格、列错位、非法字符清洗） |
| `differ/` | `normalize.py` | 归一化（繁简、全半角、空白、分隔符） |
| | `diff_engine.py` | 匹配键对齐 + 差异分类（SAME/CHANGED/ONLY_ORIG/ONLY_PLM）+ 置信度 |
| | `group_diff.py` | 分组（按章节/分组标题）对齐 |
| | `ordering.py` | 输出排序 |
| | `resolve.py` | 人工决策解析（接受/拒绝/手动匹配/相同/拆分 五态） |
| | `audit.py` | 审计报告（可追溯每条差异） |
| `rules/` | `loader.py` + `data/*.yaml` | 正向规则 + 反向规则（误报防护），YAML 可版本化 |
| `suggester/` | — | 建议：规则化动作 + LLM/mock 变更项归纳 |
| `writer/` | — | 生成整合清单 + 对照表 docx（词级红字 + 黄色高亮） |
| `memory/` | `feedback_store.py` | 决策落盘 JSONL + 指纹聚合读回反哺建议（详见 `记忆库说明.md`） |
| `nodes.py` / `pipeline.py` | — | 流程节点与串联 |
| `trace.py` | — | 运行 trace |

其它：`graph/`（LangGraph 编排）、`webapi/`（含 `analytics.py` 使用统计）、`frontend/`（Vite+React，确认页 `ReviewPage.tsx`）。

## 6. 怎么跑（详见 README.md）

```bash
pip install -r requirements.txt
cp .env.example .env            # 用 llm 模式填 LLM_*；mock 模式可跳过

# 冒烟（无需 Word/LLM）
python cli.py --orig-json fixtures/orig.json --plm-json fixtures/plm.json --out runs/out

# 真实 doc + 真 LLM
python cli.py --orig 原报告清单.doc --plm PLM导出清单.doc --out runs/out --mode llm

# Web（后端 8000 + 前端 3000）
python -m webapi
cd frontend && npm install && npm run dev     # 默认账号 admin/admin
```
