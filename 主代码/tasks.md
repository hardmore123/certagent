# Implementation Plan: 报告草稿准确性核对

> 独立项目。当前只做“认证资料超集 + 报告草稿清单 → 双文档输出”。
> 分专业路由只完成设计预留，待业务划分规则确定后再部署。
> 不修改 CertAgent 生产项目，不接入 KOA/Tims。

## Overview

本计划按 P0–P7 拆解：先验证 Word 批注，再实现超集定位、逐字核对、双文档输出、独立 Web 接入；分专业路由与多轮审批作为后续阶段。

## P0：样本、边界与技术可行性

- [x] **T01 固化输入样本和字段基线**
  - 确认认证资料超集样本、报告草稿样本及版本号；
  - 记录文档类型、表数量、目标子块、字段名和预期行数；
  - 输出 `samples/manifest.json` 与字段映射初稿；
  - 验收：两份输入角色明确，所有目标子块均有样本定位。

- [x] **T02 完成 Word 批注最小 PoC**
  - 用 10~20 行最小 docx 验证 `python-docx 1.2.0` 的 `add_comment`；
  - 验证批注能写到指定表格单元格并被 Word 打开；
  - 验证无法精确定位时可退化到单元格首段；
  - 验收：生成可打开的批注版 docx，批注作者和内容正确。

- [x] **T03 建立项目运行骨架**
  - 创建独立 Python 包、CLI、`runs/out`、`samples`、`tests` 目录；
  - 只复制/适配必要的现有解析、规则和模型，不修改源项目；
  - 验收：空流程可运行，输入输出目录和配置边界清晰。

## P1：两侧文档解析

- [x] **T04 实现认证资料超集定位器 `cert_locator`**
  - 遍历认证资料全部表格；
  - 通过表头指纹识别安全清单、EMC 清单、变更确认表、产品描述字段；
  - 图片页、声明页及未识别表保留元数据，不静默丢弃；
  - 验收：输出每个目标子块的表索引、表类型、表头、行数和原始文本。

- [x] **T05 实现报告草稿解析与批注锚点**
  - 复用清单解析器解析规整报告草稿；
  - 每个字段保存 `table_idx / row_idx / cell_idx / para_hint`；
  - 保留原始字段文本，不在解析阶段覆盖显示内容；
  - 验收：任一差异字段都能回定位到报告草稿的单元格或段落。

- [x] **T06 完成 CERT/DRAFT 字段映射**
  - 统一表头别名、字段名称和表块类型；
  - 处理不同列数、合并单元格、空值和多值型号；
  - 记录无法映射的字段并提示人工确认；
  - 验收：安全、EMC、变更确认、产品描述四类字段均有映射结果。
## P2：逐字核对引擎与规则

- [x] **T07 设计并实现核对数据模型**
  - 定义 `Anchor`、`LocatedBlock`、`VerifyDiff`、`VerifyResult`；
  - 差异字段使用 `cert_value` 与 `draft_value`，明确应然/实然方向；
  - 差异类型至少包括 `field_mismatch`、`missing_in_draft`、`extra_in_draft`；
  - 预留 `discipline`、`discipline_status`、`rule_version`、`round_no`，但默认不路由；
  - 验收：模型可序列化 JSON，任一差异可追溯到 CERT 子块和 DRAFT 锚点。

- [x] **T08 实现逐字段核对 `verify_differ`**
  - 以 CERT 为基准，逐子块、逐行、逐字段对齐；
  - 优先使用确定性匹配键，避免仅用名称或型号造成误匹配；
  - 同名同型号但证书号、位号、分组或规格不同，分别保留；
  - 验收：同项字段变化、认证资料独有、报告草稿独有均分类正确。

- [x] **T09 实现无意义差异规则配置**
  - 建立可版本化、可回放的归一化配置；
  - 默认忽略外层空白、连续空白、大小写、全半角和明确等价波浪线；
  - 证书号、型号、规格数值、位号、制造商和生产企业等实质字符差异必须保留；新增规则须经过业务确认；
  - 保留原文用于展示，归一化值只用于判断；
  - 验收：默认规则命中的格式差异判一致，规则外实质差异不被吞掉。

- [x] **T10 设计分专业路由预留模型**
  - 定义专业枚举：电路、电源、模组光学、结构、认证、产品线总经理；
  - 定义规则表、规则版本、生效状态、未命中状态、多专业关联；
  - 未确定规则前所有差异为 `discipline_pending`；
  - LLM 仅可输出候选专业和理由，不能自动写入最终路由；
  - 验收：可加载未来规则但当前运行不会自动分配或触发审批。

- [x] **T11 生成可解释 diff 与 trace**
  - 保存输入文件摘要、定位结果、字段映射、归一化前后值、匹配键和差异集；
  - 每个差异有稳定 `key` 与 `sig`；
  - 验收：任一汇总条目可反查 CERT 表/行/字段与 DRAFT 表/行/字段。

## P3：双文档输出

- [x] **T12 实现报告草稿批注 writer**
  - 输入原始 DRAFT docx 和差异集，输出批注版 DRAFT；
  - 批注内容包含差异字段、认证资料值、报告草稿值和差异类型；
  - 批注优先落到差异字段单元格，失败时落到行或单元格首段；
  - 验收：原文排版和内容尽量保留，批注可在 Word 中查看。

- [x] **T13 实现差异汇总 writer**
  - 输出独立 docx，差异按 1、2、3 连续编号；
  - 每项包含子块、位置、字段、CERT 值、DRAFT 值、差异类型和建议；
  - 未能批注的差异必须在汇总中保留并标注“批注锚点失败”；
  - 验收：编号唯一连续，汇总条目数等于差异集条目数。

- [x] **T14 实现双输出一致性校验**
  - 校验每个差异是否至少出现在批注版或汇总中；
  - 校验 `cert_value` / `draft_value` 方向没有交换；
  - 校验批注锚点属于 DRAFT，不属于 CERT；
  - 验收：缺失、重复、方向错误时流程失败并给出明确错误。
## P4：CLI、回归与人工确认

- [x] **T15 实现 CLI 端到端流程**
  - 参数接收 CERT 路径、DRAFT 路径、输出目录和规则配置；
  - 串联定位、解析、比对、人工确认、双输出；
  - 支持 `--mode mock` 仅用于流程验证，不替代规则结果；
  - 验收：真实样本可一次命令生成两份输出和完整 trace。

- [x] **T16 建立单元与冒烟测试**
  - 覆盖表头指纹、合并单元格、空值、多值型号、重复项和字段映射；
  - 覆盖 `field_mismatch`、`missing_in_draft`、`extra_in_draft`；
  - 覆盖无意义差异和规则外字符差异；
  - 覆盖批注锚点降级和汇总兜底；
  - 验收：测试可重复运行，失败能定位到模块和样本。

- [~] **T17 用真实样本建立金标准**
  - 对四类子块人工标注字段级一致/不一致；
  - 标注未识别表、人工补录、业务改写和无法判断项；
  - 分别统计定位召回、字段差异召回、误报率、批注定位成功率；
  - 验收：不使用“字符串命中率”代替业务准确率。

- [x] **T18 增加人工确认页**
  - 展示差异项、CERT 值、DRAFT 值、原文位置和批注预览；
  - 支持接受、忽略、修改差异说明和标记需人工复核；
  - 专业字段只展示 `discipline_pending`，暂不提供自动审批路由；
  - 验收：人工确认后才允许下载最终双文档。

- [x] **T19 接入反馈记忆**
  - 保存确认结果、理由、字段、差异类型、sig 和文档版本；
  - 记忆只影响后续建议，不得直接删除原始差异证据；
  - 验收：反馈可落盘、可查询、可回放，规则变更有版本边界。

## P5：Web 独立项目接入

- [x] **T20 建立独立 Web 任务类型**
  - 不修改 CertAgent 生产任务；
  - 新建 report-verify 任务记录、状态、输入摘要和输出路径；
  - 支持上传、进度、结果和下载；
  - 验收：任务数据与 CertAgent 运行数据隔离。

- [x] **T21 配置文件与安全边界**
  - 规则路径、输出路径、批注作者、上传大小、超时可配置；
  - 不把输入文件、报告内容、API Key 写入日志；
  - 加密/透明加密文件沿用既有识别和解密边界；
  - 验收：配置缺失时给出明确错误，不静默生成空结果。

- [x] **T22 完成 MVP 验收与项目文档**
  - 输出部署说明、样本说明、字段映射说明、已知限制和回滚方式；
  - 固化双文档验收清单；
  - 验收：另一位开发者可按文档运行、验证和解释结果。

## P7：多轮审批闭环（后续）

- [ ] **T26 设计审批状态机**
  - 草稿录入 → 专业审批 → 认证工程师汇总 → 发机构修改 → 机构回稿 → 二次审批 → 完成；
  - 每个状态保存操作人、时间、意见、附件和版本；
  - 拒绝/退回必须有修改项或附件。

- [ ] **T27 实现轮次版本对比**

  - 对比第 N 与第 N+1 轮，判断已改、未改、改错和新增差异；
  - 验收：可查看每一条原始差异的闭合状态。

- [ ] **T28 评估 KOA/Tims 集成**

  - 先用导入/导出模拟联调；
  - 外部流程失败不能破坏核对证据和版本记录。

## Notes

- P0–P5 是当前独立项目的实现范围；P6 的专业路由必须等待业务划分规则确认、评审和版本发布后才可部署。
- P7 的多轮审批、KOA/Tims 接口不进入当前 MVP，先保证核对证据、批注和差异汇总独立可用。
- 认证资料和报告草稿的原始文件不直接提交到代码仓库；应使用脱敏样本或受控数据目录。
- 当前验收重点是：定位不漏、字段逐字核对、无意义差异规则可解释、批注写入 DRAFT、汇总不漏项。
