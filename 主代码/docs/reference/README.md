# 需求与规范一手资料（docs/reference/）

这些是"为什么这样核对"的来源，交接方遇到规则疑问时回到这里查原文。

> **两个项目的边界提示**：这里的 PRD 与 CQC 规范是整个"认证智能体"业务的共同上游，同时服务于
> **项目一（CertAgent 清单整合）**和**项目二（本项目 ReportVerify 报告草稿核对）**。本目录只保留与
> 本项目核对口径直接相关的规范原文；清单整合（项目一）的输入样例/代码不在本仓库内。两个项目的
> 总体区别见工作区根目录《两个项目导读.md》。

## 与核对规则的关系

- 核对的四类子块（安全清单 / EMC 清单 / 变更确认表 / 产品描述）与字段，源头在 PRD 需求5 与 CQC 实施细则。
- "哪些字段算实质差异、哪些算格式差异"的业务判断，最终以这些规范 + 业务确认为准（见项目根 `rules/normalization.json` 与 `交接文档.md` §5）。
- 分专业路由（电路/电源/模组光学/结构/认证/总经理）的划分依据也需回到 PRD 与业务规则确认（P6，当前 BLOCKED）。
