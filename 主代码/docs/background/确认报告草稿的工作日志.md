## 一、项目定位

把认证机构出的**报告草稿（DRAFT）**拿去和企业侧的**认证资料（CERT）**逐行逐字核对，自动在报告草稿上写批注并生成编号差异汇总，供人工确认后交付。

- CERT 认证资料：超集文档（安全/EMC 关键件清单、变更确认表、产品描述、图片、声明页等），是**应然基准**。
- DRAFT 报告草稿：相对规整的关键件清单，是**被核对对象（实然）**。
- 比对最小单位：一行（参照 CertAgent 的行级双侧视图）。
- 硬边界：批注只写入 DRAFT，绝不写入 CERT；本项目独立于 CertAgent，不修改其生产代码。
- 样本角色约定：文件名 `A20` 开头 = CERT，`100` 开头 = DRAFT。

## 四、数据模型（models.py）

- `Anchor`：DRAFT 中 1-based 的 table_idx/row_idx/cell_idx/para_hint，批注定位用。
- `DocumentRow`：一行结构化字段 values + 各字段 anchors + source_table/group。
- `LocatedBlock`：一个被识别子块（block_type、表索引、表头、行）。
- `VerifyDiff`（字段级，批注与决策的唯一单元）：key/block_type/item_name/diff_type/field/cert_value/draft_value/cert_location/draft_anchor/match_status/match_reason/rule_version/review_*/row_key。
- `RowDiff`（行级，页面展示单元）：row_key/row_status/row_kind/cert_row/draft_row/cert_row_ref/draft_row_ref/changed_fields/diff_keys/match_*。
- `VerifyResult`：cert_blocks/draft_blocks/diffs/row_diffs/unrecognized_cert_tables/warnings/rule_version，序列化进 verification.json。
- 关键：VerifyDiff.row_key 与 RowDiff.diff_keys 双向回链；页面按行操作，最终仍展开成字段级 key 提交，finalize_review 逻辑不变。

## 五、匹配与核对策略

三级匹配，逐级收敛：
1. 表级（_table_candidate）：按表头 Jaccard+序列、分组 token、名称、型号、行数加权打分，为每个 CERT 物理表选一个 DRAFT 表；一张 DRAFT 表可承接多个 CERT 分表。已固化：CERT 表7/20→DRAFT 表1、CERT 表28→DRAFT 表2。
2. 表内行级（_match_rows）：以分组上下文+名称+型号为候选，型号支持 equal/subset/overlap/wildcard_equal 集合关系；名称不同时须型号集合关系成立且证书号相同（或规格+位号同时相同）才配对。全局按候选质量一对一多重集消费，重复行不折叠、不错配。
3. 字段级（LIST_FIELDS）：逐字段 same_value 判等，不同即 field_mismatch。

已固化业务规则：型号尾部通配符（******/*）折叠为“型号族键”仅用于身份匹配、原文差异保留；受限名称包含（主板 ↔ 主板(含网卡、含调谐单元)）仅在同表、型号族相同、分组兼容时提名并标 needs_review；子块/整表缺失不虚构物理行，产出 row_kind="block" 提示行。
safety_list/emc_list 走表级+行级；product_description/change_confirmation 走按“项目”identity 分组比较。

行级状态：配对无差异=SAME、配对有差异=CHANGED、CERT 独有=ONLY_CERT、DRAFT 独有=ONLY_DRAFT。

## 六、归一化规则（rules/normalization.json，版本 normalized-v2）

原文只用于展示，判等只用归一化值；规则带版本号、可回放，LLM 不得擅自扩大忽略范围。只作用于字段判等 same_value，不影响行匹配。当前默认启用（enabled）：

| 规则 | 作用 |
|---|---|
| trim_outer_space | 去首尾空白 |
| collapse_whitespace | 连续空白（含换行）压成一个空格 |
| casefold | 大小写 |
| fullwidth_ascii | 全角→半角 |
| wave_dash | ～ → ~ |
| list_separator | 换行/分号/顿号/逗号等列表分隔符视为等价（顺序敏感） |
| strip_all_space | 忽略所有内部空白（标准号/型号内部空格视为格式差异） |
| placeholder_blank | `/`、`-`、`—`、`–`、`N/A`、`NA`、`None` 等占位符视为空 |

证书号、型号、规格数值、制造商、生产企业、认证标准、备注、变更前后值等实质字符差异仍必须核对。严格模式（传 enabled: []）关闭全部规则。

## 七、Web API 与前端

FastAPI（webapi/app.py，独立数据目录 runs/web_jobs/<job_id>/，与 CertAgent 隔离）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/health | 健康探针 |
| POST | /api/jobs | 上传 CERT+DRAFT，异步核对 |
| GET | /api/jobs、/api/jobs/{id} | 任务列表/详情 |
| GET | /api/jobs/{id}/diffs | 字段级差异（分页，旧接口，兼容保留） |
| GET | /api/jobs/{id}/row-diffs | 行级差异：两侧完整行+状态+diff_keys+决策状态 |
| POST | /api/jobs/{id}/decisions | 提交决策（按 key 集合校验，处理缺失/未知 key） |
| GET | /api/jobs/{id}/result/{draft\|summary} | 全部确认后才可下载最终双文档 |
| GET | /api/jobs/{id}/memory | 反馈记忆提示 |

前端 frontend/index.html（单文件内联，无构建链）：CERT/DRAFT 左右并排（左 CERT｜中关系符号 ＝ ≠ ← →｜右 DRAFT），字段展开/折叠、差异高亮、全部/只看待确认筛选、跳到下一个待确认、分页全量加载、行级决策映射到字段级 key。
