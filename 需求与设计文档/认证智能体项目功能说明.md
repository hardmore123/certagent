# CertAgent 认证智能体项目功能说明

> 项目：CertAgent 认证智能体
> 当前核心版本：Linux 生产树 `c:\Users\likunyuan\Desktop\项目\CertAgent\Linux`
> 正式规划访问地址：`http://10.18.87.51/certagent/`

## 一、项目定位

CertAgent 面向认证工程师，将两份认证关键件清单进行自动解析、差异识别、业务归纳、人工确认和 Word 结果生成，减少人工逐行比对工作，并沉淀确认经验供后续任务参考。

核心流程：

```text
上传原始/旧版清单 + PLM/新版清单
        ↓
文档解析与格式校验
        ↓
行级差异比对 + 关键件组级归纳
        ↓
规则建议 / 可选 AI 智能配对
        ↓
人工确认、拒绝、手动匹配和填写理由
        ↓
生成整合清单 + 变更前后对照表
        ↓
数据守恒审计 + 长期记忆
```

## 二、当前已实现的用户功能

### 1. 用户登录

- 用户名/密码登录；
- JWT 登录态保存和接口鉴权；
- 登录后进入工作台；
- 支持退出登录。

当前是简化认证模型，默认账号用于内部 Demo/生产使用，尚未实现完整的用户、角色和权限管理。

### 2. 上传两份认证清单

用户分别上传：

- A 文件：原始清单、人工整理清单、旧版本/变更前清单；
- B 文件：PLM 导出清单、新品清单、新版本/变更后清单。

当前 Web 生产流程支持：

- `.docx`；
- `.json` fixture/结构化数据；
- 透明加密的 `.docx`，由后端调用解密服务后再解析；
- 前端按文件头识别真实 `.docx` 和 `.doc`，避免仅修改后缀名造成误解析。

`.doc` 文件当前不建议直接上传，需在 Word 中“另存为 `.docx`”后上传。
## 三、工作台功能

### 1. 任务管理

- 创建上传任务；
- 每 3 秒轮询任务状态；
- 展示任务状态：排队中、运行中、等待确认、已完成、失败；
- 展示当前阶段、进度、文件名、差异数量和错误信息；
- 同一用户查看自己的历史任务；
- 支持并发任务数限制和后台异步处理。

### 2. AI 智能配对开关

用户可在上传任务时选择是否启用 AI 智能配对。AI 只对规则比对后剩余的候选项进行疑似配对提名，并返回置信度和理由，不直接替代人工决定。

当前 Web 的业务变更归纳主要使用组级 Mock 规则；LLM 主要用于可选的模糊候选提名。CLI 可单独配置真实 LLM 做实验或运行。

### 3. 结果下载

任务完成后可下载：

- `整合版关键件清单.docx`；
- `变更前后对照表.docx`。

工作台还可查看差异摘要和数据守恒审计结果。

## 四、差异确认功能

Review 页面提供两种查看方式：

- 合并视图：查看最终整合结果中的行；
- A/B 并排视图：同时查看原始清单和 PLM 清单对应内容。

系统自动将 SAME 项视为接受，重点要求人工处理：

- B 独有：新版本新增项；
- A 独有：旧版本保留项；
- CHANGED：同一件内容发生变化；
- AI 疑似配对：名称或型号不完全一致但可能属于同一件。

人工可执行的裁决包括：

- 接受系统判断；
- 拒绝并丢弃；
- 独有项手动匹配为相同；
- 独有项手动配对为内容不同；
- 内容不同但实际相同；
- 内容不同拆分为两条独有项；
- 拒绝 AI 配对并拆开保留；
- 填写裁决理由；
- 一键接受全部剩余项；
- 跳转到下一条待确认项。

## 五、文档解析功能

解析器基于 `python-docx`，支持认证清单中的复杂 Word 结构：

- 表1主清单和表2备选件/电源单元表；
- 表头别名和字段归一化；
- 分组标题识别；
- 横向合并单元格；
- 纵向合并和跨行填充；
- 型号多值集合；
- 表格列偏移修复；
- 控制字符清洗；
- 繁体转简体；
- JSON fixture 加载；
- 透明加密文件解密后的再次解析。

解析结果会转换为统一的 `Row` 数据模型，供后续 diff、建议、输出和审计共同使用。

## 六、差异比对功能

### 1. 行级比对

系统采用确定性优先的多重集比对，核心分类包括：

- `SAME`：两侧相同；
- `CHANGED`：同一关键件但内容不同；
- `ONLY_ORIG`：仅旧版本存在；
- `ONLY_PLM`：仅新版本存在。

匹配键包含表号、分组、关键件名称、型号、位号、规格材料和证书号等信息，使用列表和消费标记保留重复物料，避免同名同型号行被错误覆盖。

### 2. 型号集合比对

当型号单元格包含多个型号时，系统可以识别：

- 新版本型号集合扩充；
- 新版本型号集合收窄；
- 两侧型号集合部分重叠。

部分重叠默认进入人工确认，不自动判定为同一件。

### 3. 关键件组级比对

系统按“表号 + 分组标题 + 关键件名称”聚合物理行，识别更接近业务语言的变化：

- 整组替换/换型；
- 整组新增；
- 整组减少；
- 选型数量变化；
- 组内供应商或选型变化；
- 相同组无变化。

行级 diff 保证数据完整和可追溯，组级 diff 用于生成对照表中的业务归纳。
## 七、AI 建议与规则功能

建议层分为两部分：

### 1. 规则建议

- 对差异类型给出默认动作；
- 根据正向规则和反向规则减少无意义差异；
- 使用历史记忆降低重复误报；
- 输出建议动作、置信度和变更字段。

### 2. LLM 建议

- 对规则无法确定的残余行提名疑似匹配对象；
- 输出配对置信度和自然语言理由；
- 组级输入用于归纳“换型、备选件变化、供应商变化”等业务描述；
- 结构化输出失败时回退到 Mock/规则建议；
- LLM 只提供建议，最终结果由人工确认。

## 八、Word 输出功能

### 1. 整合清单

- 输出表1和表2；
- 保留分组标题；
- 以 PLM 新版本作为主要输出骨架；
- 补充旧版本未消费行；
- 新增项、差异项使用红色/加粗/高亮标识；
- 增加来源信息，如 PLM 新版本、旧版本保留、两侧差异；
- 统一控制字符、繁简体和字体格式；
- 发生审计异常时可追加疑似丢失行附录。

### 2. 变更前后对照表

- 按组级差异归纳业务变化；
- 输出变更项目、变更前内容、变更后内容和建议；
- 对无法从清单推导的照片、额外型号等内容标注外部输入/人工补充；
- 支持 Mock 和 LLM 两种归纳方式。

## 九、审计与长期记忆

### 1. 数据守恒审计

输出后检查原始清单和 PLM 清单的每一行是否被保留、合并、拒绝或补录，发现 critical 级异常时追加疑似丢失行并重新审计。

### 2. 长期记忆

- 每条人工裁决以 JSONL 追加落盘；
- 保存裁决类型、理由、差异类型、关键件名称、型号和上下文；
- 使用稳定指纹跨任务聚合；
- 高频接受的模式提高置信度；
- 高频拒绝的模式降低置信度或预置忽略；
- 支持挖掘别名关系和高频误报规则；
- 记忆文件迁移到 `compare_core/memory/data/`，避免临时运行目录被清理。

主要接口包括：

| 接口 | 功能 |
|---|---|
| `GET /health` | 服务健康检查 |

## 十二、功能成熟度边界

### 已实现并可验证

- Web 登录、上传、任务状态和结果下载；
- `.docx`/JSON 解析和复杂表格处理；
- 行级和组级差异比对；
- 规则建议和可选 AI 智能配对；
- 人工确认、手动匹配、拒绝策略和理由记录；
- 整合清单、变更前后对照表和数据审计；
- 长期记忆写入、读取和建议反哺；
- API 统计、CLI 和 LangGraph 人在环流程；
- Linux、systemd、Nginx 部署材料。

### 部分实现或有条件可用

- Web 组级业务归纳当前主要走 Mock 规则，真实 LLM 需要配置并单独验证；
- `.doc` 不支持生产自动转换，需要 Word 另存为 `.docx`；
- 透明加密文件依赖解密服务；
- 任务元数据会落盘，但人工确认阶段的完整 pipeline state 主要保存在内存中，服务重启恢复能力有限；
- 统计接口已实现，但没有独立统计页面；
- 当前认证是简化 JWT 模型，尚未形成完整的角色权限体系。

### 规划中或尚未并入主 Web

- 报告草稿与认证资料的异类文档核对；
- 报告草稿 Word 批注；
- 差异汇总和多轮审批；
- PLM、SCP、云盘、档案室、KOA 等外部系统接口；
- 证书推荐、证书有效性查询和过期预警；
- 认证申请资料自动生成；
- 多用户、角色权限和数据库持久化。

## 十三、项目价值

CertAgent 已将原本需要人工逐行检查的认证清单工作，转化为“机器先解析和比对、AI 辅助归纳、人员最终确认、系统自动生成文档”的闭环。其核心价值不是完全取消人工，而是：

1. 减少 Word 表格人工查找和重复比对；
2. 降低重复行丢失、跨分组误合并和字段错位风险；
3. 将物理行差异提升为关键件组业务变化；
4. 保留每次确认的理由和可追溯证据；
5. 让历史确认结果反哺后续任务；
6. 为报告草稿准确性核对等后续认证场景提供可复用底座。
