# 两个项目导读（总入口 · 防混淆）

本工作区里有**两个相关但不同**的项目，都围绕海信"认证智能体"业务，但目标、输入输出、代码仓库各不相同。本文件是总入口，先读这里再进各自文件夹。

---

## 一句话区分

| | 项目一：认证清单整合 | 项目二：报告草稿准确性核对 |
|---|---|---|
| 代号 | **CertAgent** / list-merge | **ReportVerify** |
| 做什么 | 两份关键件**清单**对比，**整合**成一份 | 认证资料 vs 报告草稿，逐字段**核对**找差异 |
| 关键动词 | **合并 / 整合** | **核对 / 批注** |
| 输出 | 整合清单 + 变更前后对照表 | 批注版报告草稿 + 差异汇总 |
| 状态 | **已完成、已上线、已上传 GitLab** | **分支项目，未完全完成** |

一句话：**项目一把两份清单"合"成一份；项目二拿基准去"校"报告草稿对不对。** 不要混。

## 项目一：认证清单整合（CertAgent）—— 已完成/已上传

### 定位
两份 Word 关键件清单（原报告清单 / PLM 导出清单）→ 判断差异 → AI 建议 → 人工确认 → 生成【整合清单】+【变更前后对照表】，并沉淀决策记忆用于优化。

### 代码仓库（均在本工作区）
- `CertAgent/` — **已上传 GitLab 的正式仓库**，含：
  - `Linux/` 服务器部署版（FastAPI + React 构建 + nginx + systemd + 解密集成）
  - `demo/` 本地开发版（= list-merge-demo 的导出）
  - GitLab: `Full-Stack-Frontend/Hisense/Agents/AI_Applications/CertAgent.git`
- `list-merge-demo/` — 本地开发主目录（LangGraph 编排 + 核心引擎 + React 前端）

### 结构（核心引擎 compare_core）
- `parser/` 文档解析（Word COM，容错重心）
- `differ/` 归一化 + 匹配键对齐 + 差异分类 + 置信度
- `rules/` 正向规则 + 反向规则（误报防护）
- `suggester/` 规则化动作 + LLM/mock 变更项归纳
- `writer/` 生成整合清单 + 对照表 docx
- `memory/` 决策落盘 + 相似检索（长期记忆）
- `graph/` LangGraph 编排（人在环 interrupt）
- `webapi/` + `frontend/`（React/Vite）

### 输入 / 输出
- **输入样例**（就是你指出"像这个"的那些）：
  - `样例/`（75U66Q 原报告清单 / PLM导出清单 / 关键件清单 / 变更前后对照表）
  - `AI智能体-认证原始清单与新品清单合并/`（东芝 85ZXSF 等）
  - `20.认证智能体PRD/图片和附件/` 下的 75U66Q / 75VX5S 等
- **输出**：整合版关键件清单.docx + 变更前后对照表.docx（见 `list-merge-demo/runs/`）

## 项目二：报告草稿准确性核对（ReportVerify）—— 分支项目，未完全完成

### 定位
核对两份异类文档：
- **CERT 认证资料**（超集，应然基准，文件名 `A20` 开头）
- **DRAFT 报告草稿**（被核对、被批注，文件名 `100` 开头）
→ 字段级逐字核对 → 批注版 DRAFT + 编号差异汇总。LLM 仅做候选/解释辅助，人工确认 + 下载门禁不可绕过。

### 代码仓库（本工作区）
- `报告草稿准确性核对/` — 独立 FastAPI 项目，**已本地 git 初始化、尚未推 GitLab**。
  - 自带完整交接材料：`交接文档.md`、`交付清单.md`、`README.md`、`docs/`、`scripts/`、`samples/`、`tests/`

### 结构（核心包 report_verify）
- `cert_locator.py` CERT 超集按表头指纹定位目标子块
- `draft_parser.py` DRAFT 解析 + 批注锚点
- `field_map.py` / `rules.py` 字段映射 + 归一化规则
- `verify_differ.py` 逐字段核对
- `comment_writer.py` / `summary_writer.py` 批注 + 汇总 writer
- `review.py` 人工确认 + 反馈记忆
- `llm/` 可选 LLM 子包（候选/解释，默认 off）
- `webapi/` + `frontend/index.html`（单文件前端）

### 输入 / 输出
- **输入样本**：`报告草稿准确性核对/samples/data/`（100E7S DRAFT + A2026 CERT 这一对）
- **输出示例**：`报告草稿准确性核对/samples/expected_outputs/`（verification.json + 批注版 + 汇总）

### 完成度
- 确定性核对 + 双文档输出 + Web + 人工确认 + LLM 集成：已实现（357 测试通过）
- 未完成：候选阈值语义优化、9 个属性测试、分专业路由(P6)、多轮审批(P7)、业务金标准
- 详见 `报告草稿准确性核对/交接文档.md` §7、§8

## 两者关系

- 项目二**复用**了项目一的部分解析/文档处理思路，但**独立实现、独立仓库**，不改项目一生产代码。
- 两者共享上游业务背景：认证智能体 PRD、CQC 认证规范（项目二在 `docs/reference/` 留了副本）。
- **输入样例不要混用**：清单整合的 75U66Q/75VX5S/东芝样例属于项目一；报告核对的 100E7S/A2026 属于项目二。
