# 大模型接口说明（ReportVerify LLM Provider）

> 本文描述 ReportVerify 调用大模型网关的接口形态、鉴权、协议、参数、错误码与脱敏约定。
> **真实 API_KEY / USER_KEY / endpoint 不写入本文**，仅以占位符示意；真实值只存在于项目根 `.env`（已 gitignore），由受控环境注入。
> 代码实现：`report_verify/llm/client.py`（请求装配 + 响应读取）、`config.py`（配置）、`policy.py`（策略门禁）。

---

## 1. 网关与模型

- **协议**：OpenAI-compatible Chat Completions（沿用 CertAgent 已批准的约定）。
- **网关**：复用 CertAgent 聚好看 **higpt-new** 内网网关。
  - Base URL 形态：`https://<approved-host>/higpt-new/v1`（真实 host 见 `.env`，受服务器 host allowlist 约束）。
- **模型**：`deepseek-v4-flash`（推理模型，可配置）。
- **调用端点**：`POST {base_url}/chat/completions`。

> 真实部署里 host 必须在 `REPORT_VERIFY_LLM_ALLOWED_HOSTS` 内，默认要求 HTTPS（明文仅受控环境显式开启）。

---

## 2. 鉴权

| 项 | 位置 | 说明 |
|---|---|---|
| `api_key` | 请求头 `Authorization: Bearer <api_key>` | 与 CertAgent 同一受控 secret |
| `user_key` | URL query 参数（可选） | 可选 gateway 凭据 |

安全约定：`api_key` / `user_key` 只驻留内存 settings，只出现在请求头/query；**绝不进入日志、异常消息、trace、元数据或任何序列化输出**。审计元数据只记录 host、model、transport、attempts、耗时、以及 request/response 的 SHA-256 摘要哈希（不含 URL query、prompt 原文、response 原文）。

---

## 3. 请求体

```jsonc
{
  "model": "deepseek-v4-flash",
  "messages": [ { "role": "...", "content": "..." } ],
  "temperature": 0,          // 固定 0，追求确定性输出
  "stream": true,            // 默认走 SSE 流式
  "max_tokens": <可选>       // 仅当 REPORT_VERIFY_LLM_MAX_TOKENS>0 时写入
}
```

- `temperature=0`、`stream=true` 为固定语义。
- `max_tokens`：安全阀，默认 0=不写入请求体（不限制）；正整数时作为上限传给网关。

---

## 4. 响应读取

两种 transport：

- **SSE（`stream=true`）**：逐行处理 `data: {...}` / `data: [DONE]` / 空行，累积 `choices[0].delta.content`；忽略 `reasoning_content` 等非 content 字段。
- **JSON（非流式）**：读取 `choices[0].message.content`。

两条路径都施加**单行上限**与**累计响应字节上限**（`max_response_bytes`，默认 1 MiB），并处理空响应 / 非法 JSON。

**JSON 语法容错**（`repair_json`）：去除 ```` ```json ```` 围栏、截取第一个 `{...}`。只做语法层修复，业务语义/Schema 由 `schemas.py` 的 validator 校验，client 不实现 Schema。

---

## 5. 可靠性控制

| 机制 | 配置 | 说明 |
|---|---|---|
| 单次超时 | `TIMEOUT`（默认 60，本项目用 180） | 单次请求读取墙钟 |
| 总墙钟 | `TOTAL_TIMEOUT`（默认 120，本项目用 600） | 含所有重试与退避；超出不可重试 |
| 重试 | `MAX_RETRY`（默认 2） | 仅对可重试错误码；指数退避 base 0.5s、cap 8s |
| 断路器 | `CIRCUIT_FAILURE_THRESHOLD`(3) / `CIRCUIT_COOLDOWN`(60) | 连续失败达阈值后冷却期短路 |

---

## 6. 错误码（分类，code 见 `client.py`）

| code | 含义 | 可重试 |
|---|---|---|
| `llm_response_empty` | SSE/JSON 均未提取到 content | 是 |
| `llm_response_too_large` | 超过单行/累计字节上限 | 否 |
| `llm_http_error` | 连接错误 / 暂时性 5xx | 是 |
| `llm_rate_limited` | 429 | 是（墙钟内有限重试） |
| `llm_attempt_timeout` | 单次读取超时 | 是 |
| `llm_total_timeout` | 超过总墙钟 | 否 |
| `llm_auth_failed` | 401/403 | 否 |
| `llm_circuit_open` | 断路器冷却中 | 否 |
| `llm_misconfigured` | 配置不完整 | 否 |
| `llm_policy_denied` | 策略门禁拒绝（host/TLS/原文/图片/行数等） | 否 |

错误消息里绝不放响应正文或凭据。

---

## 7. 两种能力的调用用途

- **candidate（候选匹配）**：确定性键无法对齐的跨文档行，给出"可能同项"的候选 + 置信度 + 理由（`orchestrator.py`）。
- **explain（差异解释）**：对已判差异给自然语言解释与风险（`explain.py`），按 `max_rows` 分批 + 范围上限 `EXPLAIN_MAX_DIFFS` + 线程池并发 `EXPLAIN_MAX_WORKERS`。

两者都是**只读参考**，不改变确定性结论、不改变下载门禁。产物以脱敏证据 sidecar（`llm-evidence.json`）落盘，只存脱敏计数与结果，不存 prompt/response 原文。

---

## 8. 策略门禁（provider 调用前强制）

`policy.py` + `release_gate.py` 在组装 payload / 发网络请求前强制：
- host 在 allowlist、TLS 默认 HTTPS；
- 任务 mode 只能选 allowlist 内值，禁止越权覆盖 provider/model/endpoint/key/原文/图片策略；
- 字段原文受字段白名单 + 字符上限 + 行数上限（`max_rows=200` 硬上限）+ 脱敏约束；
- **图片能力固定硬拒绝**（`allow_images=False`，构造函数强制，任何开启尝试都记为无效并 fail closed）。

启用前先跑：`python -m report_verify.llm.release_gate`（只读非敏感配置、不访问 provider）。详见 `LLM_RELEASE_GATE.md`。

---

## 9. 真实配置在哪里

真实 host / key / model 只在项目根 **`.env`**（已 gitignore）。配置项全集与占位示例见 **`.env.example`**。当前本地启用形态（脱敏描述）：

```text
MODE=candidate_explain
BASE_URL=https://<内网 higpt-new 网关>/higpt-new/v1
MODEL=deepseek-v4-flash
API_KEY / USER_KEY = <受控注入，不入库>
ALLOWED_HOSTS=<内网网关 host>
ALLOWED_MODES=off,candidate,explain,candidate_explain
TIMEOUT=180  TOTAL_TIMEOUT=600
EXPLAIN_BATCH_ROWS=50  EXPLAIN_MAX_DIFFS=500  EXPLAIN_MAX_WORKERS=4
```

> 接手方若需真实联调：向凭据持有人索取受控注入的 key，写入本地 `.env`（勿提交），跑门禁通过后再启用。生产默认保持 `MODE=off`。
