## 一、整体诉求

CCC 认证的"准备资料"阶段，用 AI 替代人工完成**关键件清单的生成审核、整合、扩点排查**，核心目的：提效 + 防止量产一致性检查不合格。

三节共享同一套数据底座与产物类型：
- **数据源**：PLM 关键件清单/BOM、认证报告（试验报告 PDF）、零部件认证信息、规则文件（Excel）。
- **核心能力**：全部围绕"清单的审核 / 对比 / 提取"——即**文档结构化 + 规则化比对**（与《项目整体梳理》结论一致）。
- **产物**：各类关键件清单（.doc）、对照表、评估表（.docx）、机型清单（Excel）。

## 二、逐节需求细节

### 3.1.1.1 全新 —— 关键件清单审核

| 项 | 内容 |
|---|---|
| 角色 | 电路/电源/模组光学/结构工程师、认定工程师 |
| 场景 | 导出关键件清单 |
| 需求 | PLM 生成的关键件清单文件，AI **依据规则审核**并输出审核结果（规则变动则规则库更新）|
| 输入 | ① PLM《安全&EMC关键件清单》(.doc)；② 规则文件《产品认证关键件清单及照片V3版》(.xlsx) |
| 输出 | 审核结果 + 《安全&EMC关键件清单》 |
| 操作路径 | PLM→认证管理→认证资料包→选对应资料包→生成关键件清单文件 |
| 价值 | 省电路工程师收集整理时间 0.5H/项目；提升一致性检查合格率 |
| 验收 | 《安全&EMC关键件清单》 |

要点/注意：
- 这是**"单份清单 vs 规则库"的审核**，不是两清单对比（区别于 3.1.1.2）。
- 原"2、关键件清单信息审核及修订补充"（认定工程师二供信息比对）在 PRD 中**已划删**，不在本期范围。

### 3.1.1.2 变更-开发 —— 含两个子需求

**A. 两份清单整合（本项目 Demo 已实现）**

| 项 | 内容 |
|---|---|
| 角色 | 电路/电源/模组光学/结构/认定工程师 |
| 场景 | 各专业对比原报告，整合输出变更后的关键件清单 |
| 需求 | 将 PLM 新生成清单 + 派生原报告清单输入 AI，整合（**重复合并 / 非重复标红加粗 / 备注来源**），生成汇总版关键件清单 + 变更前后对照表 |
| 输入 | `75U66Q(01)_PLM导出清单.doc`（变更后来源）+ `75U66Q(01)_原报告清单.doc`（变更前基准）|
| 输出 | ① `75U66Q(01)_安全&EMC关键件清单.doc`（整合版）② `75U66N变更前后对照表.doc` |
| 下游 | 整合清单 + 对照表 + 企业承诺书 + 型号差异声明 + 新型号铭牌 → 提交 KOA 3C 认证变更流程 → 各模块工程师(资料准备性)+认定工程师(扩点资源)审批 → 认证工程师发起变更申请 |

格式：清单为 .doc，表1（关键件主清单 10 列）+ 表2（备选件表）；对照表 3 列（变更项目/变更前/变更后）。详见《需求说明_变更开发清单整合》。

**B. 推荐变更原证书**

| 项 | 内容 |
|---|---|
| 角色 | 电路/电源工程师、产品经理、认证工程师 |
| 场景 | AI 自动推荐新机型变更认证选取的变更原证书 |
| 需求 | 根据新增型号，AI 对比 PLM 上**相同电源板、主板**的型号，按规则推荐差异化最合适的原证书型号 |
| 输出 | 原证书型号 |
| 价值 | 减少各专业反复线下沟通，快速定原证书，最大化减少认证费用 |

要点/注意：
- 与 CB 全新的"电源板差异比对 TOP5"是**同类能力**（按组件/位号比差异），可复用。
- 强依赖 **PLM 接口**（查电源板/主板组件、被引用机型、状态）。

### 3.1.1.3 变更-物料扩点 —— 排查 + 评估表

| 项 | 内容 |
|---|---|
| 角色 | 认定工程师 |
| 场景 | 安规物料扩点排查；频次：1 物料查约 500 机型，年约 100 物料，人工约 0.5H/机型 |
| 需求链路 | ① 排查扩点物料涉及机型/整机状态/销售国家 → ② 逐机型排查证书报备现状，确认是否含拟扩点供方安规信息（**PDF 技术难点**）→ ③ 提取未报备拟扩点供方/型号的机型清单 → ④ 每个机型生成需变更的安全件清单，输出简化备案评估表 |

详细 SOP（原文）：
1. PLM 按**物料号**反查所有应用机型 → 导出机型清单。
2. 机型清单交产品经理确认在产机型 → 输出在产机型清单；机型清单增"证书号""报备状态"两列。
   - 规则：状态字段(立项/开发/上市/退市)，退市可删；**但防退市尾单，参考 SCP 13+9 计划（接口待确认）**。
3. 输入扩点物料信息：型号、规格、厂家名称、证书号。
4. 逐机型在认证工程师共享云盘查认证报告，确认是否已含拟扩点供方认证信息：
   - 找证书号 + 《国家强制性产品认证试验报告》；有→报备状态"已报备"，无→"未报备"，找不到证书→证书号记"/"、状态记"未找到该证书"。
   - **一个报告可能带多个电源板，关键件名称重复，需全部提取**。
   - 未报备的：提取"该证书号仅含该关键件"的清单（word，变更前清单，AI 导出）→ 下面加行补拟扩点供方信息（变更后清单，可人工加）。
   - 场景2：当地转认证（印度 BIS、台湾 BSMI）需找产品经理要报告，操作同上。
5. 未报备机型清单按相同证书号分类整理成 sheet2（AI 输出）：机型清单(含内外销)、认证类型、认证号、认证文件。
6. 查 CQC-C0901-2023 细则确认扩点品类关键件等级（Class A / B，**人工确认**）：
   - Class A：每机型一个流程；
   - Class B（通常）：走简化备案，按每个证书号生成《CCC 认证变更简化流程申请及评估表》(AI 输出)；
   - 外销(CB/UL/S-MARK)：每机型一个流程。
7–8. 费用核算/发起流程（PRD 标注**不需要**）。

| 项 | 内容 |
|---|---|
| 输入 | 扩点物料信息(型号/规格/厂家/证书号)；PLM 机型清单；认证报告 PDF；CQC-C0901-2023 细则 PDF；评估表模板 `GYZ002-R01…docx` |
| 输出 | ① 在产机型清单(+证书号/报备状态列)；② 未报备机型清单(sheet2 按证书号分类)；③ 变更前/变更后清单(word)；④《CCC 认证变更简化流程申请及评估表》 |
| 价值 | 减少人工排查与遗漏，25000H/项目 |
| 验收 | 安规物料扩点无因认证问题导致整机一致性检查不合格 |

## 四、共性问题与注意事项

1. **文档解析是底座**：涉及 .doc / .docx / .xlsx / **PDF（认证报告，最难）**。PRD 两处明确 PDF 解析准确率为技术难点。
2. **对比是主线能力**：三节本质都是"审核/对比/提取"，可共用一套解析+比对引擎。
3. **规则来自 Excel**：如《产品认证关键件清单及照片V3版》《CQC-C0901 细则》，都是给人看的文件，需转成机器可执行规则。
4. **强依赖外部接口**：PLM（反查机型/组件/状态/BOM）、SCP（13+9，待确认）、共享云盘/多维表格。
5. **准确率红线**：PRD 要求 100%——对含 LLM/PDF 解析的环节不现实，应采用"宁可多标不漏 + 人工确认"兜底。
6. **规则散落**：interchangeable、Class A/B、退市尾单判定等规则分散在正文/附件，需集中沉淀。

## 五、需要完善 / 未阐述清晰的信息（关键）

**3.1.1.2 变更-开发**

- B 推荐原证书：
  - "**差异化最合适**"的判定规则未定义（差异物料最少？认证费用最低？还是综合？）；
  - 依赖 PLM 提供：电源板/主板**组件号**、被引用机型、机型状态——**接口/字段需确认**；
  - 与 CB 全新"电源板差异比对 TOP5"的规则是否统一，需确认。

**3.1.1.3 变更-物料扩点**
- ① **"在产机型"判定**：PLM 是否有明确字段/规则？退市尾单需 **SCP 13+9 接口（PRD 标注待确认）**。
- ② **认证报告 PDF 解析**：报告格式不统一、解析准确率——PRD 点名技术难点，需评估方案与容错。
- ③ **数据源位置**：认证报告目前在"认证工程师共享云盘"（后续建多维表格/PLM），当前是否有稳定可读的数据源未定。
- ④ **Class A/B 判定**：需查 CQC-C0901 细则，PRD 说"人工确认"——AI 是否只做候选提示需明确。
- ⑤ **评估表字段来源**：《CCC 认证变更简化流程申请及评估表》各字段从哪取（物料信息/机型/证书号），需字段级映射。
- ⑥ "一个报告多电源板、关键件名称重复需全部提取"——**提取规则需明确**（如何界定"该证书号仅含该关键件"的清单范围）。
- ⑦ **拟扩点供方信息比对口径**：供方名称确定，但与报告中报备信息的匹配规则（名称/型号/规格/证书号哪些为准）未定义。

**通用待提供**

- 各类模板文件的字段说明（评估表、承诺书、型号差异声明、铭牌）。

这句话是 3.1.1.2-A（清单整合）的核心需求。我逐片段拆开讲，每段标注是否有依据（来自 PRD 原文 / 来自样例文件 / 无依据需推测），并尽量用 75U66Q 样例举真实例子。

先一句话概括：把"新机型 PLM 导出的关键件清单"和"从旧证书派生出来的原报告清单"两份 Word 喂给 AI，AI 合并成一份完整清单（新增/差异的地方标红加粗并注明来自哪份），同时另出一份"变更前后对照表"。

逐片段拆解
① "PLM系统生成的关键件清单文件"

含义：本次要做认证的新机型，从 PLM 系统导出的关键件清单。代表"变更后"的目标状态。
举例：75U66Q(01)_PLM导出清单.doc。
依据：✓ PRD 原文 + 样例文件名。文件真实结构（表1 关键件主清单 + 表2 备选件表）是我们解析样例得到的，PRD 未写。
② "派生原报告清单文件"

含义："派生"指新机型不单独送检，而是挂靠一个已有的旧证书/原报告做认证变更；这份就是那个旧证书对应的原报告关键件清单。代表"变更前"的基准。
举例：75U66Q(01)_原报告清单.doc。
依据：✓ PRD 原文 + 样例。但"派生的原证书是怎么选出来的"属于另一个需求（3.1.1.2-B 推荐原证书），不在这句话里。
③ "输入AI智能体"

含义：两份 .doc 作为输入交给 AI。
依据：✓ 原文。输入必须是这两份、格式是否只支持 .doc——⚠ 未明确。
④ "两份文件整合"

含义：把两份清单按"同一个关键件项"对齐后合成一份。
依据：✓ 原文说了"整合"。但**"以什么为一条记录、按什么匹配"完全没说**（是按关键件名称？型号？证书号？）——⚠ 无依据，需推测/确认。这正是我们 Demo 里要定的"匹配键"。
⑤ "重复资料合并"

含义：两份里都有、且相同的项，只保留一份，不重复列。
举例：两份清单里同一个"电线组件 + 型号 HL-007… + 证书号 2007010101232657"都存在 → 合并成一条。
依据：✓ 原文说了"重复合并"。但**"什么算重复"没定义**——完全逐字相同？还是忽略空格/全半角/波浪号后相同？（样例里就有 250V～ vs 250V~ 这种）——⚠ 无依据，是我们 Demo 用"归一化"补上的推测规则。
⑥ "非重复资料整合并标红加粗"

含义：只在某一份里有、或两份内容不一致的项，也要并进汇总清单，并把这些新增/差异内容标红加粗，让人一眼看到变了什么。
举例：原报告没有、PLM 新增的"机内电源单元 型号 12269-H（对应 75U66N）"→ 合并进去并整行标红加粗。
依据：✓ 原文明确"标红加粗"。但标红加粗的精确范围（整行？还是只标差异字段？）、颜色值、是否加批注——⚠ 未说明。
⑦ "备注资料来源自哪份文件"

含义：对这些非重复项，要注明它来自"PLM 导出清单"还是"原报告清单"。
举例：某新增项后面注一句"来源：PLM导出"。
依据：✓ 原文说了"备注来源"。但备注写在哪里（新增一列"资料来源"？写进现有"备注"列？还是加批注？）——⚠ 未说明。
⑧ "生成一份汇总版关键件清单文件"

含义：整合后的最终产物之一，一份完整的"变更后关键件清单"。
举例：75U66Q(01)_安全&EMC关键件清单.doc。
依据：✓ 原文 + 样例。但输出是否要保留原始复杂表结构（分组标题行、合并单元格、多型号排版）——⚠ 未说明（我们 Demo 目前只输出简化平铺表）。

含义：除了整合清单，还要另出一张对照表，逐条说明"改了什么、改之前是什么、改之后是什么"，给审批人看。
