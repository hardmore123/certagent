# 实现思路 v2：变更-开发 清单整合（LangGraph + 可复用核心引擎）

> 配套：《需求说明_变更开发清单整合.md》《项目整体梳理.md》
> 本版变化：整合 pdf-reviewer 的设计借鉴，把"单个 Demo"升级为"可向全项目复用的核心引擎 + 薄编排层"的分层框架，并明确分层目标。
> 最高原则：**把 AI 当不可靠组件做工程封装；能用代码保证确定性就不交给模型；自动只到出建议，落库/改规则必须人工确认。**

---

## 一、实现目标（分三层）

| 层级 | 目标 | 交付 |
|---|---|---|
| **L1 Demo 目标（本期）** | 两份 Word 清单 → 判断差异 → 出建议 → 人点是/否 → 生成整合清单+对照表 → 记录决策 | 能端到端跑通 75U66Q 样例的可运行 Demo |
| **L2 引擎目标（中期）** | 沉淀通用"文档结构化解析 + 差异比对 + 规则库/反向规则 + 反馈闭环"核心包 | 独立可复用的 `compare-core` 包 |
| **L3 项目目标（长期）** | 该引擎横向复用到 PRD 其它对比类任务（清单审核 3a/4a、清单vs信息库 5、报告草稿核对 6、供方信息审核 8a） | 认证智能体的"对比/核对"能力底座 |

**Demo 的成功判据**：不是"规则多全/准确率多高"，而是"解析→对比→建议→人确认→修改→记忆"这条闭环能稳定跑通，且每一步中间结果对人可见、可反馈。

---

## 二、核心设计理念（借鉴 pdf-reviewer 后确立）

1. **对抗"不可信"的重心 = 解析层，而非模型层**。本任务的 diff 是确定性代码，最不可信的是 .doc 解析（跨行合并、一格多型号、分组标题行、老二进制）。把 pdf-reviewer 的"畸形枚举 + 兜底 + trace 落盘 + 人工可见校验"平移到解析层。
2. **能代码就不用模型**：judge(diff) 全代码保证确定性；LLM 只用于 suggest 的"变更项归纳"和难判定项的相似判断。
3. **规则驱动 + 反向规则压误报**：正向规则管"怎么比"，反向规则管"什么差异不算差异"。
4. **人工可控可回滚**：自动只到"出建议"，改规则/落库必须人工确认；规则写前自动备份。
5. **依赖单向、核心可移植**：核心引擎不依赖 LangGraph/前端；编排与 UI 是薄层。

## 四、从 pdf-reviewer 的借鉴映射（架构决策依据）

| pdf-reviewer 设计点 | 用不用 | 在本项目怎么落 |
|---|---|---|
| 1 双模型交叉验证+仲裁 | **改造** | 不做双模型（diff 是确定性代码）。只借**置信度分层**：完全匹配=high 自动过；格式/模糊差异=low 重点让人确认 |
| 2 规则驱动+双层表示 | **抄** | `.md`(人看)+`yaml`(代码筛选)；category 管目标、标签管范围；Demo 用最小规则集 |
| 3 反向规则库(误报防护) | **抄(高价值)** | 压制格式类误报（全半角/空格/单位/证书号大小写）；`pattern+instruction+examples` |
| 4 规则学习闭环 | **抄(高价值)** | 反馈落盘→阈值触发→LLM 出建议→**人工审批落库**；rule_stats 记 acceptance_rate |
| 5 统一定位器 6 层降级 | **改造** | Word 有结构坐标(表/行/列 cell)，不需模糊降级；只借"定位算一次、稳定写回"用于标注回写 |
| 6 LLM 输出容错 | **抄(必须)** | suggest 输出 try/except+类型检查+缺省+重试+trace 落盘 |
| 7 独立包+依赖单向 | **抄** | compare-core 独立可 CLI 单跑；core 不反向依赖编排/UI |
| 8 Web 工程化 | **部分/后置** | 先抄"规则写前自动备份可回滚"；JWT/并发/看板后置 |
| 视觉审查路 | **跳过** | 无图像审查需求 |

**一句话**：LLM 容错、反向规则、反馈闭环、独立包架构 → 直接抄；置信度分层、备份回滚 → 轻量借；双模型、6 层定位、视觉 → 跳过；对抗不可信的重心从模型层挪到**解析层**。

## 五、数据流：判断 → 建议 → 人确认 → 修改 → 记忆

```
[上传两份 .doc]
   │
1 parse(代码)   .doc → 结构化行；畸形枚举兜底；结果落 trace 供核对
   │
2 judge(代码)   归一化 → 匹配键对齐 → diff 分类 + 每项置信度
                (重复/仅原报告/仅PLM/内容差异)
   │
3 suggest       ① 先查记忆：相似历史决策命中→复用/few-shot，降低人工项
   (规则+LLM)    ② 每个 diff 出建议动作+理由+命中规则+置信度
                ③ 行级 diff → 归纳为对照表业务变更项 (LLM，输出强容错)
   │
4 human_review  ★interrupt：展示差异确认表(含 AI 理由/命中规则/置信度
   (人在环)       + parse/judge 中间产物)；用户逐项 是/否/改
   │  (resume 带决策)
5 apply(代码)    生成 整合清单.docx(标红加粗+来源) + 对照表.docx
   │
6 memory        用户决策落盘反馈库；被否建议→反向规则候选；统计更新
```

### 置信度分层（借鉴点1的改造）
- **high**：归一化后完全匹配 → 自动合并/自动判定，不打扰人
- **medium**：单侧存在的明确新增 → 建议标红，人快速确认
- **low**：格式/措辞差异、LLM 归纳项 → 重点人工确认
> 目标：让人只花时间在真正不确定的项上，其余自动化。

## 六、规则库 + 反向规则

```
rules/
├ merge_rules.yaml        # 正向：匹配键 / 归一化 / 标注 / 变更项分类
├ merge_rules.md          # 人话版说明（给人和 LLM 看）
└ avoidance/
   └ false_positive.yaml  # 反向：pattern + instruction + examples
```
反向规则示例（来自"用户反复否掉"的模式）：
```yaml
- pattern: 证书号大小写
  instruction: 证书号仅大小写/空格差异不算内容差异
  examples: ["2007010101232657" 与 "2007010101232657 " 视为相同]
```

## 七、反馈闭环 + 双层记忆

- **短期（会话内）**：LangGraph Checkpointer，支持中断恢复、反复调整。
- **长期（跨会话）**：反馈库(结构化 JSON) + Store。三档促进：
  1. **即时复用**：suggest 前按 context 检索相似历史决策 → 命中即复用/做 few-shot。
  2. **反向规则沉淀**：被反复 reject 的建议 → 落入 avoidance，下次不再报。
  3. **规则提炼(半自动，后置)**：积累到阈值 → LLM 出规则建议 → **人工审批** → 落 merge_rules。
- **红线**：LLM 只出建议；改规则/落库人工确认；规则写前自动备份可回滚。

### 第 6 条显式拆解：提示词 + 编排 + 后处理
- **提示词（Prompt）**：仅在 `suggester` 节点。两类——① 行级 diff 归纳为对照表变更项；② 难判定项"是否同一件"的相似判断。prompt 末尾注入长期记忆命中的 few-shot 示例。
- **编排（Orchestration）**：LangGraph StateGraph 串 parse→judge→suggest→[interrupt]→apply→memory；Checkpointer 支持中断恢复。
- **后处理（Post-process）**：① LLM 输出一律 `try/except + 类型检查 + 缺省 + 重试 + trace 落盘`；② `writer` 把结构化决策转成 Word 富文本（标红加粗 + 来源备注 + 对照表）。
