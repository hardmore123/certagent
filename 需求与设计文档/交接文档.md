## 1. 这个项目在做什么

核对两份 Word 文档，产出"哪里对不上"的证据：

- **CERT 认证资料**（应然基准，超集）：多表文档，含安全清单、EMC 清单、变更确认表、产品描述，还有图片、声明页等无关内容。文件名以 `A20` 开头。
- **DRAFT 报告草稿**（实然对象，被核对、被批注）：相对规整的关键件清单。文件名以 `100` 开头。
- **输出**：① 批注版 DRAFT（差异批注写在报告草稿对应单元格）；② 编号差异汇总 docx（1、2、3… 连续编号，含 CERT 值 / DRAFT 值 / 差异类型 / 位置）。

核心边界（贯穿全项目，务必遵守）：

1. **确定性核对优先**。是否"有差异"由严格逐字段比较决定，规则带版本号、可回放。
2. **LLM 仅辅助**，只做"候选匹配"和"差异解释"，是只读参考，**不改变确定性结论、不改变下载门禁**。
3. **人工确认 + 下载门禁不可绕过**。全部差异人工确认前，禁止下载最终文档。
4. CERT 是应然值、DRAFT 是实然值，方向不可交换；批注只能落在 DRAFT。
5. 本项目独立于 CertAgent 主项目，复用其解析/模型/网关凭据思路，但不修改 CertAgent 生产代码。

## 2. 快速上手

推荐直接用一键脚本（详见 `scripts/README.md`）：

```powershell
.\scripts\run_web.ps1       # 启动服务（自动清理残留 LLM 环境变量）
.\scripts\run_sample.ps1    # 用内置样本跑一次完整核对
.\scripts\run_tests.ps1     # 全量测试（357 项）
.\scripts\check_llm.ps1     # LLM 配置自检 + 发布门禁
```

等价的原始指令：

```powershell
# 1) 安装依赖（固定版本）
python -m pip install -r requirements.txt

# 2) 跑单元测试（全部应通过）
python -m unittest discover -s tests -v

# 3) 启动 Web（后端 API + 前端静态页同一进程托管）
uvicorn webapi.app:app --host 0.0.0.0 --port 8010
# 浏览器打开 http://127.0.0.1:8010/
```

或命令行一次性核对（见 `samples/README.md` 的示例路径）：

```powershell
python cli.py --cert <CERT.docx> --draft <DRAFT.docx> --out runs\myrun
```

依赖：`python-docx 1.2.0`、`fastapi`、`uvicorn`。`.doc` 会由 `converter.py` 经 Word COM / LibreOffice 自动转 `.docx`。

### 环境变量与 .env

- 复制 `.env.example` 为 `.env` 填入受控凭据。`.env` 已被 gitignore，**禁止把真实 API_KEY / USER_KEY / endpoint 入库**。
- 启动时 `report_verify/env_bootstrap.py` 自动加载项目根 `.env`，**真实环境变量优先、不覆盖**。
- 若父 shell 残留了进程级 `REPORT_VERIFY_LLM_*`（尤其 `=off`），会压过 `.env`。启动前先清：
  ```powershell
  Remove-Item Env:REPORT_VERIFY_LLM_* -ErrorAction SilentlyContinue
  ```

## 4. 处理流程（确定性主链）

```text
CERT 超集 ──→ converter(.doc→.docx) ──→ document_parser ──→ cert_locator ─┐
                                                       （表头指纹定位子块）  │
DRAFT 清单 ─→ converter ─→ document_parser ─→ draft_parser ────────────────┤
                                               （保存批注锚点）             │
                                                                           ▼
          field_map（字段映射）──→ rules（归一化）──→ verify_differ（逐字段核对）
                                                              │
                                          ┌───────────────────┼───────────────────┐
                                          ▼                   ▼                   ▼
                                 comment_writer        summary_writer       （可选）llm 子包
                                 批注版 DRAFT           编号差异汇总          候选/解释 只读证据
                                          └─────── validation 一致性校验 ───────┘
                                                              │
                                              review 人工确认 + 下载门禁
```

要点：
- **定位不漏**：CERT 未识别的表不静默丢弃，进 unrecognized 元数据提示人工复核。
- **锚点降级**：批注优先落差异字段单元格，失败则退到行/单元格首段；再失败则该差异只进汇总并标注"批注锚点失败"，绝不生成假的"无差异"。
- **可追溯**：每个差异有稳定 `key` 与 `sig`，可反查 CERT 表/行/字段 ↔ DRAFT 表/行/字段。

## 5. 核对规则（判定口径，重点）

规则文件：`rules/normalization.json`，版本 `normalized-v2`。原文仅用于展示，**归一化值只用于判断**。LLM 不得擅自扩大忽略范围。

当前默认启用（`enabled`）的归一化项及含义：

| 规则键 | 作用 | 判一致的例子 |
|---|---|---|
| `trim_outer_space` | 忽略首尾空白 | `" ABC "` = `"ABC"` |
| `collapse_whitespace` | 连续空白压成一个 | `"A   B"` = `"A B"` |
| `casefold` | 大小写不敏感 | `"abc"` = `"ABC"` |
| `fullwidth_ascii` | 全角/半角 ASCII 等价 | `"ＡＢＣ"` = `"ABC"` |
| `wave_dash` | 明确等价波浪线归一 | `"〜"` = `"~"` |
| `list_separator` | 换行/分号/顿号/逗号等分隔符等价（**顺序仍敏感**） | `"A、B"` = `"A;B"`（但 `"A,B"` ≠ `"B,A"`） |
| `strip_all_space` | 忽略所有内部空白（标准号/型号内部空格视为格式差异） | `"IEC 60065"` = `"IEC60065"` |
| `placeholder_blank` | `/`、`-`、`N/A` 等占位符视为空 | `"/"` = 空 |

**仍然保留（判差异）的实质字符差异**：证书号、型号、规格数值、位号、制造商、生产企业、认证标准、备注、变更前后值等。

规则治理原则：
- 规则带版本号、可通过 `enabled` 显式增减，变更须经业务确认。
- 新增"忽略规则"会放大"判一致"的范围，属于高风险操作，务必评审。

## 6. LLM 集成（可选、只读辅助）

> 代码在 `report_verify/llm/`，完整 spec 在 `docs/specs/report-draft-llm-integration/`，**接口形态/鉴权/协议/参数/错误码见 `docs/大模型接口说明.md`**。生产默认 `MODE=off`。真实网关地址与密钥只在项目根 `.env`（已 gitignore）。

### 6.1 两种能力

- **candidate（候选匹配）**：当 CERT/DRAFT 行无法用确定性键对齐时，给出跨文档"可能是同一项"的候选配对 + 置信度 + 理由。只读参考。
- **explain（差异解释）**：对已判定的差异，用自然语言解释差异点与潜在风险（可含候选专业建议）。只读参考。
- 组合模式 `candidate_explain` 同时产出两者。

### 6.2 LLM 子包模块职责

| 模块 | 职责 |
|---|---|
| `config.py` | 从 `REPORT_VERIFY_LLM_*` 构造不可变 `LLMSettings`；凭据绝不序列化/记录 |
| `policy.py` | 服务器策略：字段白名单、`max_rows`(=200 硬上限)、字符上限、脱敏档位、host/TLS |
| `jobmode.py` | 任务级 mode 授权：只能选 allowlist 内 mode，禁止越权覆盖 provider/model/endpoint/key/原文/图片策略 |
| `client.py` | provider transport；transport 前重复校验 host/TLS/mode/原文/图片，配置被绕过时 fail closed |
| `circuit.py` | 断路器：连续失败达阈值后冷却期短路，保护墙钟预算 |
| `evidence.py` | 组装/读写脱敏证据 sidecar（`llm-evidence.json`）；只存脱敏计数与结果 |
| `explain.py` | 差异解释：按 `max_rows` 分批 + 范围上限 + 线程池并发；超上限只解释前 N 条 |
| `orchestrator.py` | candidate 编排：组装 payload、调用、校验、落证据 |
| `discipline.py` | 候选专业建议（电路/电源/模组光学/结构/认证/总经理），只给候选不自动路由 |
| `recheck.py` | 复核辅助 |
| `schemas.py` | 响应 Schema 与字段长度校验（防越长文本夹带指令） |
| `release_gate.py` | 发布门禁：本地检查配置是否可安全启用，不访问 provider |

### 6.3 安全启用 / 关闭 / 回滚

- 启用前跑门禁（只读非敏感配置、不访问 provider）：
  ```powershell
  python -m report_verify.llm.release_gate
  ```
  退出码 0 = 安全关闭或已通过全部激活门禁；1 = 有门禁失败，provider 保持关闭。门禁清单见 `LLM_RELEASE_GATE.md`。
- **最小回滚**：服务器配置切回 `REPORT_VERIFY_LLM_MODE=off` 并重启。切回后新任务不调 provider，确定性证据/人工确认/下载门禁语义不变。若要同时阻断任务级选择，再把 `REPORT_VERIFY_LLM_ALLOWED_MODES=off`。
- 回滚不需要复制/轮换/打印任何 key，不删除原文，不改 CertAgent。

### 6.4 关键配置（全集见 `.env.example` 与 `config.py`）

- `MODE` / `ALLOWED_MODES` / `ALLOWED_HOSTS`：开关与 allowlist
- `BASE_URL` / `MODEL` / `API_KEY` / `USER_KEY`：复用 CertAgent 聚好看 higpt-new 网关（deepseek-v4-flash），受控注入
- `TIMEOUT` / `TOTAL_TIMEOUT`：单次 / 总墙钟（本项目实测用 180 / 600）
- `EXPLAIN_BATCH_ROWS=50` / `EXPLAIN_MAX_DIFFS=500` / `EXPLAIN_MAX_WORKERS=4`：解释分批/上限/并发
- `ALLOW_ORIGINAL_TEXT=true`（允许字段原文，受白名单约束）/ `ALLOW_IMAGES=false`（图片硬拒绝，构造函数强制）

### 本周（截至 2026-09-03）新增/修复

1. **LLM 集成启用并真实验证**：`.env` 复用 CertAgent 网关，`env_bootstrap` 自动加载；真实链路跑通。
2. **差异解释分批 + 范围上限 + 并发**：解决单批 200 行超墙钟问题；上限 200→**500**。
3. **候选跨文档护栏修复**：相容判断从"物理表号相等"改为"block_type 相同 + 分组相容"。
4. **前端重写**：青色三视图（工作台/历史记录/确认差异）+ LLM 开关 + AI 建议只读区。
5. **AI 解释行内内联**：按 `diff_key` 把解释渲染到每行差异正下方的只读卡片。

7. **任务计时**：后端记 `started_at/finished_at/timings`（解析核对/AI解释/总耗时），前端运行期实时"已用时 mm:ss" + 完成后阶段明细 + 历史"耗时"列。

## 8. 已设计但未实现（接手重点）

### 8.1 候选阈值语义优化（方案 F，建议最先做）

现状：`validate_response` 对候选是"整批否决"——只要有一个 `confidence < 0.6` 的配对，就拒绝整批合规候选（触发 `llm_safety_rejected`）。诊断示例：模型返回 6 配对，valid=4/below=2 → 整体被拒。
建议：改为"低于阈值的配对逐条丢弃、只有结构违规（Schema/越权）才整批拒绝"，并补回归测试。入口在 LLM 子包的候选校验路径（`orchestrator.py` / `schemas.py` 附近）。

### 8.2 可选属性测试补齐

LLM 集成 spec 还有 9 个可选属性测试（4.6–4.14）未做，覆盖分批边界、并发、截断标记、护栏等正确性。参考 `tests/test_llm_task44_properties.py` 的写法。

### 8.3 分专业路由（P6，BLOCKED）

- `tasks.md` T23–T25：已定义专业枚举（电路/电源/模组光学/结构/认证/产品线总经理）、规则表/版本/生效状态/未命中状态/多专业关联的**数据结构与配置接口**，`discipline.py` 可输出候选专业，但：

  - 必须等业务确认划分规则（按哪些字段/部件/子块路由、是否允许多专业、总经理汇总/升级边界）并评审通过后，才实现规则引擎（规则优先于 LLM、未命中进人工分配）与汇总分节/路由预览。

### 8.4 多轮审批闭环（P7，未实现）

| POST | `/api/jobs/{id}/decisions` | 提交人工确认；全部确认后才生成/放行最终文档 |
| GET | `/api/jobs/{id}/result/{draft\|summary}` | 下载批注版 DRAFT / 差异汇总（受门禁） |

任务产物落在 `runs/web_jobs/<job_id>/`（已 gitignore）。单进程 uvicorn：asyncio 单线程，任务注册表进程内 + 落盘 + 重启恢复。

## 10. 验证与排错

- **全量测试**：`python -m unittest discover -s tests -v`（应全通过）。
- **发布门禁**：`python -m report_verify.llm.release_gate`。
- **终端输出易截断**（Windows PowerShell）：诊断建议写入 `runs/_*.txt`/`.json` 再读。
- **父 shell 残留 `REPORT_VERIFY_LLM_*`** 会压过 `.env`，启动前先 `Remove-Item Env:REPORT_VERIFY_LLM_*`。
- **内网网关偶发 SSLError**：来源准入波动导致，非代码问题，重试或联系网关侧。
- **大文件慢**：141MB CERT 解析 + LLM 会明显变慢，用任务计时定位是卡在"解析核对"还是"AI 解释"。
