变更-开发 关键件清单整合 Demo 的首个可跑通快照。

---

## 一、版本定位

- 目标层级：L1 Demo（详见《实现思路_变更清单整合Demo.md》）。
- 成功判据：**解析→判断→建议→人确认→修改→记忆** 全闭环可跑通，中间结果可见、可反馈。
- 决策基线：CLI 前端；suggest 用真 LLM（限定 JSON 结构化输出）并保留 Mock；核心引擎独立不依赖 LangGraph。

## 三、架构

分层，依赖单向（上层依赖下层，核心不反向依赖编排/UI）：

```
CLI(cli.py)
   │
   ├─ engine=core → compare_core/pipeline.py（顺序编排）
   └─ engine=graph → graph/build.py（LangGraph + interrupt 人在环）
                          │  二者都复用 ↓
                compare_core/nodes.py（判断/建议/修改/记忆）
                          │
   parser → differ → rules → suggester(规则+LLM/mock) → writer → memory
```

数据流：`parse → judge(diff) → suggest → [human_review] → apply → memory`

设计理念（借鉴 pdf-reviewer）：
- 对抗"不可信"的重心在**解析层**（畸形枚举 + 兜底 + trace 落盘 + 结果可核对）。
- 能代码保证确定性就不用模型：diff 纯代码，LLM 只做对照表变更项归纳。
- 正向规则 + 反向规则（误报防护）；人工可控、可回滚（改规则须人工确认）。

## 四、已实现功能

1. **文档解析（Word COM）**，并已在真实样例上验证处理以下畸形：
   - 分组标题行（"以下部分适用于整机结构1…"）识别进 `group`；
   - 纵向合并（序号/关键件名称跨行）→ 跨行填充 carry；
   - 横向合并（型号+规格/材料 合并一格导致正文比表头少一列）→ 合并点后列号 +1 回对齐；
   - 控制字符清洗（解析层 + 写回层双重）；
   - 证书号从"备注"列取值。
2. **差异比对引擎（纯代码）**：归一化 + 匹配键对齐，产出 4 类差异（重复/仅原报告/仅PLM/内容差异）+ 置信度（high/medium/low）。
3. **建议生成**：确定性规则动作（merge/mark_new/mark_diff/ignore）+ 对照表变更项归纳（mock 朴素 / 真 LLM 结构化）。
4. **Word 生成**：整合版关键件清单（新增/差异行标红加粗 + 来源）+ 变更前后对照表。
5. **人在环**：CLI 逐项 是/否 确认；LangGraph 版用 `interrupt/Command(resume)`。
6. **长期记忆雏形**：用户决策落盘 JSONL + 关键字相似检索。
7. **可观测**：各阶段 trace 落盘（parse/diff/suggestions/changes/decisions/LLM 原始输出）。
8. **双引擎**：core 顺序编排（可无 LangGraph 单跑）与 LangGraph 编排等价复用同一套节点。

### 验证记录（2026-07-17）
- `tests/smoke.py`：mock + 构造 fixture，SAME/CHANGED/ONLY_PLM 分类正确，两份 docx 生成 → SMOKE_OK。
- `tests/smoke_graph.py`：LangGraph interrupt/resume 跑通 → SMOKE_GRAPH_OK。
- `tests/parse_real.py`：真实 75U66Q 两份 .doc 各解析 **475 行**（表1:438/表2:37），字段（含证书号）正确落位。
- `tests/real_e2e.py`：真实解析数据端到端跑通，生成两份 docx → REAL_E2E_OK。

## 五、存在的不足

**功能/规则层**
1. 匹配键仅 `关键件名称+型号`，**型号单元格一格多值未拆分**，可能把多个报备项当成一条，影响匹配粒度。
2. 规则库为最小集；反向规则仅 2 条示例；变更项分类模板未与真实对照表结构完全对齐。
3. 对照表变更项归纳偏朴素（mock 按名称聚合）；LLM 版未用真实差异对验证归纳质量。
4. **照片类变更**（外观/铭牌照片）清单无数据，Demo 无法生成，需人工/额外输入（未实现）。
5. 表2（备选件表）的"本次使用/备用"未纳入整合逻辑与标注。

**写回/输出层**
6. 整合清单为简化平铺表，**未还原原始复杂表结构**（分组标题行、合并单元格、多型号排版）；仅标红加粗，无 Word 批注。
7. 输出列固定为 8 列，未完全复刻样例清单格式。

**工程/架构层**
8. 解析依赖 **Word COM（pywin32）**，无 Word 环境不可用；大表 `Range.Cells` 逐格读取**较慢**（数百行需数十秒），未做批量/缓存优化。
9. LangGraph 内存 checkpointer 序列化 Pydantic 对象有 **forward-compat 警告**（未来版本可能被阻断），未注册模块或改存 dict。
10. 长期记忆检索仅关键字匹配，未上向量检索；规则自动提炼（learn 闭环）未实现，仅落盘。
11. LLM 未接真实内网接口验证（需配 `.env`），当前默认回退 mock。
12. 无正式单测框架（仅冒烟脚本）；无并发/大批量文件处理。

**数据层**
13. 当前 75U66Q 样例的原报告清单与 PLM 导出清单为同一基线（193 唯一件全 SAME），**未用一对真正有差异的文件**验证"合并+标红+对照表"实际效果。
